---
title: 'Execute Agent'
description: 'Run an agent by creating a session and executing a message against it'
---

There is no single-call "create and execute" endpoint. Running an agent is a two-step flow:

<Steps>
  <Step title="Create a session">
    `POST /api/v1/sessions/` with the full system configuration as the raw request body (same shape as [YAML Configuration](/guides/yaml-configuration) - not wrapped in a `system_config` key). See [Create Session](/api-reference/sessions/create) for the full reference.

    ```bash cURL
    curl -X POST https://api-be.atthene.com/api/v1/sessions/ \
      -H "x-api-key: YOUR_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "name": "Quick Answer Agent",
        "description": "Answers questions concisely",
        "entry_point": "assistant",
        "agents": [
          {
            "name": "assistant",
            "agent_type": "llm_agent",
            "system_prompt": "You provide concise, accurate answers to questions.",
            "llm_config": {
              "model": "gpt-4o",
              "temperature": 0.3
            }
          }
        ],
        "edges": [
          {"from": "__start__", "to": "assistant"},
          {"from": "assistant", "to": "__end__"}
        ]
      }'
    ```

    ```json Response
    {
      "success": true,
      "session_id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
      "config_hash": "a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8a9b0c1d2e3f4a5b6c7d8e9f0a1b2"
    }
    ```
  </Step>

  <Step title="Execute a message in that session">
    `POST /api/v1/runtime/{session_id}/execute/` with the user message. See [Execute Message](/api-reference/runtime/execute) for the full reference, including streaming and response event shapes.

    ```bash cURL
    curl -X POST https://api-be.atthene.com/api/v1/runtime/3fa85f64-5717-4562-b3fc-2c963f66afa6/execute/ \
      -H "x-api-key: YOUR_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "content": "What is the capital of France?"
      }'
    ```
  </Step>
</Steps>

<Tip>
If you'll reuse the same configuration repeatedly, save it once as an [agent](/api-reference/agents/create) and create sessions from it via [`GET /api/v1/sessions/from-agent/`](/api-reference/sessions/from-agent) instead of re-sending the full config on every session.
</Tip>

<Info>
Sessions persist conversation history - each `execute` call continues the same session rather than starting a stateless one-off interaction.
</Info>
