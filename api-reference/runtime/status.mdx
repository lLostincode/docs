---
title: 'Session Status'
openapi: 'GET /api/v1/runtime/{session_id}/status/'
---

Check session health and status.

<ParamField path="session_id" type="string" required>
  The session ID
</ParamField>

<CodeGroup>
```bash cURL
curl -X GET https://api-be.atthene.com/api/v1/runtime/session_abc123/status/ \
  -H "x-api-key: YOUR_API_KEY"
```

```python Python
import requests

response = requests.get(
    "https://api-be.atthene.com/api/v1/runtime/session_abc123/status/",
    headers={"x-api-key": "YOUR_API_KEY"}
)
status = response.json()
```

```javascript JavaScript
const response = await fetch('https://api-be.atthene.com/api/v1/runtime/session_abc123/status/', {
  headers: {
    'x-api-key': 'YOUR_API_KEY'
  }
});
const status = await response.json();
```
</CodeGroup>

## Response

```json
{
  "id": "session_abc123",
  "status": "completed",
  "created_at": 1736936000,
  "updated_at": 1736937005,
  "title": "Support Session"
}
```

<Note>
`created_at` and `updated_at` are Unix timestamps (seconds). This endpoint does not return `message_count` - use [List Sessions](/api-reference/sessions/list) or [Get Session](/api-reference/sessions/get) for that.
</Note>

## Status Values

<AccordionGroup>
  <Accordion title="initialized">
    Session created but no execution has run yet
  </Accordion>
  <Accordion title="queued">
    An execution has been queued and is waiting to start
  </Accordion>
  <Accordion title="running">
    Session is currently processing a message
  </Accordion>
  <Accordion title="completed">
    Last execution finished successfully
  </Accordion>
  <Accordion title="cancelled">
    The running execution was cancelled
  </Accordion>
  <Accordion title="error">
    Session encountered an error and may need attention
  </Accordion>
</AccordionGroup>
